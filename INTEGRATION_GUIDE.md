## 1. Архитектура интеграции (Seamless Wallet)

Платформа работает по модели **Seamless Wallet (Бесшовный кошелек)**. Единым источником правды для баланса игрока является локальная база данных казино (таблица `users`, поле `game_balance` / `balance`).

```
 ┌──────────────────────┐         1. game_launch          ┌───────────────────────────┐
 │                      ├────────────────────────────────►│                           │
 │   CROWDPLAY Casino   │                                 │   Nexus GGR Game Server   │
 │   (Laravel + React)  │◄────────────────────────────────┤   (https://api.nexusggr.dev) │
 │                      │        launch_url (iframe)      │                           │
 └──────────┬───────────┘                                 └─────────────┬─────────────┘
            │                                                           │
            │               2. POST /gold_api (user_balance)            │
            │◄──────────────────────────────────────────────────────────┤
            ├──────────────────────────────────────────────────────────►│
            │                   {status: 1, user_balance}               │
            │                                                           │
            │               3. POST /gold_api (transaction)             │
            │◄──────────────────────────────────────────────────────────┤
            ├──────────────────────────────────────────────────────────►│
            │                   {status: 1, user_balance}               │
            ▼                                                           ▼
    [ MySQL Database ]                                          [ Slot RNG & Reels ]
```

### Жизненный цикл сессии:
1. **Запуск игры (`game_launch`)**:
   - Казино отправляет POST-запрос на `https://api.nexusggr.dev` (`method: "game_launch"`).
   - Обязательные параметры:
     - `agent_code`: `"crowdplay"`
     - `agent_token`: `"c9540f990614ec0e60efa22d4c5fe5fe"`
     - `user_code`: Идентификатор игрока (например, `"user_1"`)
     - `provider_code`: Код провайдера (`"PRAGMATIC"`, `"PGSOFT"`, `"AMUSNET"`, `"HACKSAW"` и др.)
     - `game_code`: Уникальный код слота (например, `"vs10bbfmission"`, `"vs20doghouse"`)
     - `lang`: Язык интерфейса (`"en"`, `"ru"`)
     - `lobby_url`: URL возврата в лобби
   - В ответ агрегатор возвращает защищенную сессионную ссылку `launch_url`, которая открывается в iframe на странице `/game/{slug}`.

2. **Запрос баланса перед запуском (`user_balance`)**:
   - Игровой сервер обращается к вебхуку казино `POST /gold_api`.
   - Казино валидирует учетные данные агента и возвращает баланс игрока.

3. **Списание и начисление спинов (`transaction`)**:
   - При каждом вращении барабанов сервер провайдера отправляет запрос с деталями спина (`bet_money`, `win_money`, `round_id`, `txn_id`, `txn_id_v2`, `txn_type`: `debit_credit` / `debit` / `credit`).
   - Казино выполняет атомарное обновление баланса в транзакции БД и возвращает актуальный `user_balance`.

## 2. Критически важные правила Webhook (`/gold_api`)

> [!IMPORTANT]
> **1. Всегда возвращать HTTP 200 OK**:
> Все ответы на вебхук (включая ошибки валидации, нехватку средств или блокировку пользователя) **всегда должны возвращать HTTP статус 200**. 
> Если сервер возвращает HTTP `4xx` или `5xx`, игровой движок провайдера (Cloudflare / Express) считает соединение разорванным и показывает игроку **`SERVER_ERROR`**. Сама ошибка передается внутри JSON-тела: `{"status": 0, "msg": "INSUFFICIENT_USER_FUNDS"}`.

> [!IMPORTANT]
> **2. Полная структура JSON ответа**:
> Для совместимости со всеми провайдерами ответ должен содержать как `user_balance`, так и `balance`, а также подтверждающий статус:
> ```json
> {
>   "status": 1,
>   "msg": "SUCCESS",
>   "user_balance": 28064.60,
>   "balance": 28064.60
> }
> ```

> [!IMPORTANT]
> **3. Идемпотентность и защита от повторных списаний**:
> - Перед списанием проверяется уникальность транзакции по `txn_id_v2` (или связке `txn_id` + `txn_type`).
> - При повторной отправке одного и того же `txn_id` дубликат не списывает деньги повторно, а возвращает актуальный баланс со статусом `1`.

> [!IMPORTANT]
> **4. Атомарность транзакций (`lockForUpdate`)**:
> - Строка пользователя в БД блокируется через `DB::transaction()` и `lockForUpdate()` на время списания/начисления, защищая от race conditions при быстрых спинах (Turbo Spins / Auto Spins).

## 3. Управление отдачей слотов и заносами (RTP Architecture)

### ⚠️ Почему нельзя подменять выигрыш в Webhook (`GgrTransactionController`):
- Анимация барабанов, выпадение скаттеров, фриспинов и расчет выигрышных линий происходят на игровом сервере провайдера (Pragmatic / PG Soft).
- Если изменить `win_money` вручную в PHP-коде вебхука, баланс изменится, но на экране игрок увидит визуальный рассинхрон (на барабанах проигрыш, а баланс вырос).

### ✅ Как правильно настраивать заносы через Nexus API:
- Настройка отдачи производится через серверный метод `control_rtp` (`https://api.nexusggr.dev`).
- **Допустимые значения повышенного RTP**:
  `[200, 300, 400, 500, 600, 700, 800, 900, 999]` (от 200% до 999%).
- При установке RTP игроку через `AdminController::setUserRtp` команда отправляется на игровой сервер, который напрямую меняет поведение RNG слота (реальные анимации заносов, бонусные раунды и мега-множители).
